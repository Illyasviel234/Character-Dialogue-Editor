# 脚本使用说明

按角色声纹剪辑动画片段。所有脚本位于 `work/`，路径统一由 `work/core/paths.py` 推导，整个项目目录可整体搬移。

## 环境

| 项目 | 位置 |
|---|---|
| Python 解释器 | `.venv/Scripts/python.exe`（Python 3.12） |
| 语音识别模型 | `models/models--Systran--faster-whisper-large-v3` |
| 声纹模型 | `models/spkrec-ecapa-voxceleb` |
| ffmpeg | `tools/ffmpeg/bin/ffmpeg.exe` |
| 源视频 | `input/` |

运行方式（在 `work/` 目录下）：

```bash
../.venv/Scripts/python.exe -u 脚本名.py
```

全部脚本都支持 `--video`，省略时自动取 `input/` 下第一个视频。**不需要再手工改代码里的路径或编号。**

## 流水线

| 步骤 | 脚本 | 产物（在 `work/jobs/<源ID>/`） | 耗时 |
|---|---|---|---|
| 1 | `extract_audio.py` | `runs/<run_id>/audio16k.wav` + `audio.json`，并创建本次运行 | ~10 秒 |
| 2 | `transcribe.py` | `transcript.json` + `manifest.json` | ~2.5 分钟（GPU） |
| 3 | `voiceprint.py` | `embeddings.npz` | ~15 秒 |
| 4 | `select.py` | `selected.json` | ~1 秒 |
| 5 | `cut.py` | `output/<源名>_<角色>_clip.mp4`（路径可指定） | ~1 分钟（4K） |
| 6 | `gen_report.py` | 同目录下 `<源名>_<角色>_清单.html/.csv` | ~1 秒 |

辅助脚本：`verify.py`（环境自检）、`eval_threshold.py`（阈值评估）、`import_legacy.py`（手动导入旧缓存）、`migrate_jobs.py`（旧任务目录升级）。

## 任务目录与运行状态

每个源视频对应 `work/jobs/<文件名>-<内容指纹>/`。指纹是**整个文件**的流式 BLAKE2b，不是头尾采样——早期版本只读首尾各 1 MiB，两个头尾相同、中间不同的文件会算成同一个 ID，复用错误的转写与时间码。788 MB 片源完整哈希约 1 秒，结果按（路径, 大小, 纳秒修改时间）缓存在 `work/.cache/fingerprints.json`。

```
work/jobs/re0_1_08-a59803e863c31582/
├── manifest.json              源身份 + 运行记录
├── selected.json              切点方案（schema 2：源 ID、run、音轨、指纹、每段时长）
├── labels.json                人工核对结果（点「保存人工样本」后生成）
└── runs/20261023-111240-72ee95/
    ├── audio.json             这份 16k 音频来自第几条音轨
    ├── audio16k.wav           分析音频（与转写同生命周期）
    ├── transcript.json
    └── embeddings.npz
```

分析分三阶段提交：`running` → `transcribed` → `complete`。声纹阶段结束会校验两份产物是否自洽才标记 `complete`：

- 转写带 `source_id` 与 `run_id`，且与本次运行一致
- 声纹维度 192、行数等于编号数、编号无重复
- 向量全部有限、无零向量
- 每条声纹都能在本次转写里找到对应台词
- 运行记录的音轨号与 `audio.json` 一致，且音频文件存在

音频按 run 隔离：每次抽取只写自己的 `runs/<run_id>/`，先写 `.tmp.wav` 再原子替换。新分析失败或取消时，旧活动 run 的音频、转写、声纹、试听都不受影响。

**只有 `complete` 的活动运行会被读取。** 转写成功但声纹失败时，这次运行停在 `transcribed`，不会被当成完整结果使用。

开始新分析时，之前停在 `running`/`transcribed` 的运行会被标记为 `abandoned`，并由 `cleanup_runs()` 连同 `failed` 一起回收——进程被强杀也不会留下孤立目录。

### 导出前的校验

`cut.py`、`gen_report.py` 和界面导出都会调用同一个 `validate_selection()`：

- schema 版本为 2（旧方案明确拒绝）
- `source_id` 必填且与当前视频一致，源指纹一致
- `run_id` **等于当前活动运行**，否则拒绝并要求重新生成
- **`audio_track` 等于活动运行所用音轨**
- 每段 `dur` 与 `end - start` 一致（±1 ms）、有限正数、落在源时长内
- 引用的台词编号都存在于当前转写

重新分析后忘了重新筛选时，命令行不会静默用旧时间码切片：

```
切点方案不可用：切点方案来自旧运行 20200101-000000-deadbe（当前 20261023-111240-72ee95），请重新生成切点方案
```

旧版扁平缓存（`work/transcript.json`）不自动迁移——它没有来源指纹，无法判断属于哪个视频。需要手动确认：

```bash
python import_legacy.py --yes
```

指纹算法升级（v3 → v4）后，旧任务目录 ID 会失配。迁移脚本按清单记录的源路径重算指纹，确认大小与时长都没变才改名，同时改写 runs 里的 `source_id` 和 `selected.json`：

```bash
python migrate_jobs.py --dry-run    # 先看会改什么
python migrate_jobs.py              # 执行
```

## 各脚本说明

### extract_audio.py

```bash
python extract_audio.py                       # 默认 input/ 下第一个视频、第 1 条音轨
python extract_audio.py --video D:/其他.mp4
python extract_audio.py --audio-track 1       # 多音轨素材取第 2 条
```

抽指定音轨转 16 kHz 单声道，视频本体不动。**这一步会创建本次运行**，音频写进 `runs/<run_id>/`，同时记下音轨号；转写和声纹接续这个运行。换音轨后旧运行会因为音轨号对不上被 `validate_run` 拒绝，不会出现"新音频配旧转写"。

`--run <run_id>` 可以指定接续已有运行（断点重跑时用）。

### transcribe.py

```bash
python transcribe.py                          # 默认 large-v3 + cuda
python transcribe.py --model medium --device cpu
```

- `cuda` 初始化失败会自动回退 CPU，日志打印 `[warn]`，与 README 承诺一致
- 只读本地模型（`local_files_only=True`），不会联网下载
- 针对动画的调优：`condition_on_previous_text=False` 抑制 BGM 导致的重复幻觉，`word_timestamps=True` 保留词级时间戳，`vad_filter=True` 过滤纯音乐段

### voiceprint.py

```bash
python voiceprint.py              # 只提声纹，主流程
python voiceprint.py --cluster    # 附带聚类诊断
```

主流程只产出 `embeddings.npz`。聚类已移出主流水线——它在动画素材上效果不稳定（轮廓系数约 0.06），且不影响角色判定，只作为 `--cluster` 的可选观察项。

### select.py

```bash
python select.py --role 碧翠丝                                # 特征词自动挑选 + 阈值筛选
python select.py --role 碧翠丝 --selected-ids 132,133,137     # 精确指定要保留的台词
python select.py --role 碧翠丝 --selected-ids 132,133 --seed-ids 132,133  # 同时指定模板种子
```

参数：`--role`、`--selected-ids`（旧名 `--ids` 仍兼容）、`--seed-ids`、`--keyword`、`--threshold`（默认 0.66）、`--merge-gap`、`--pad-head`、`--pad-tail`。

"要保留哪些台词"和"用什么建立声纹模板"是两个概念，这里分开：

- 自动模式：特征词命中 → 建模板 → 全片打分 → 按阈值筛选
- 显式 `--selected-ids`：只按给定编号选，**不再偷偷套用默认特征词**。没给 `--seed-ids` 就不生成相似度分数，避免用错角色的模板打分

合并规则：

- 相邻台词间隔 ≤ `merge-gap` 且中间没有其他角色插话 → 合并
- 每段前后留出呼吸空间，会自动避让相邻的其他角色语段
- 短于 0.6 秒的碎片按原始边界回退

### cut.py

```bash
python cut.py                                  # 默认保持源规格，输出到 output/
python cut.py --scale 1920:1080 --crf 20       # 缩到 1080p
python cut.py --output D:/out.mp4              # 指定成片路径（相对路径转绝对路径）
python cut.py --out-dir D:/clips               # 只改目录，文件名仍按规则生成
python cut.py --audio-track 0                  # 断言用第 1 条音轨，与分析不符会报错
python cut.py --vfr preserve                   # VFR 素材保留源时间戳
```

采用**单次 filter graph 编码**：所有片段作为独立输入 seek 到各自位置，经 `setpts/asetpts` 归零后在 concat filter 里拼接，只做一次编码。避免"每段分别编码再流复制拼接"的 AAC 延迟与时间戳累积。

- 切点先吸附到帧网格再编码，保证每段是整数帧（`--vfr preserve` 时跳过这步）
- 默认 `--scale native`：不缩放、不强制帧率
- 显式缩放用 `force_original_aspect_ratio=decrease` 加黑边补齐
- 导出带 `-map_metadata -1 -map_chapters -1`：源的章节在 MP4 里会变成一条 `bin_data` 数据轨，还带着原标题和章节名，与剪辑无关，全部丢弃
- **输出路径与源视频相同时直接拒绝**，否则 `os.replace` 会把原片替换成剪辑版
- 音轨由活动运行决定，`--audio-track` 只是断言：与分析音轨不符会直接报错，换音轨必须重新分析
- `--vfr cfr`（默认）转恒定帧率、切点吸附帧网格，实测偏差 41 ms；`--vfr preserve` 不吸附、不传 `-r`，保住原始时间戳，偏差会到 300 ms 量级
- 源为可变帧率时会打印 `[warn]` 说明当前策略
- 编码完成后会打印计划时长与实际视频流时长的偏差，超过 50 ms 会告警
- 最终文件先写 `.tmp.mp4`，成功后才替换正式文件

### gen_report.py

```bash
python gen_report.py
python gen_report.py --out-dir D:/clips        # 与成片放在同一目录
```

标题、原片时长、保留比例、文件名全部来自 `selected.json` 与 `manifest.json`，不再写死作品和角色。文件名格式 `<源名>_<角色>_清单.html`，不同任务不会互相覆盖。生成前同样会校验切点方案是否属于当前活动运行。

### verify.py

```bash
python verify.py
```

逐项检查：目录结构、ffmpeg、模型文件、源视频探测、whisper 加载（含 CPU 回退）、ECAPA 加载、切点合法性。探针音频从源视频临时截取，不依赖仓库里的固定文件。任何一项失败返回退出码 1。

### eval_threshold.py

```bash
python eval_threshold.py                  # 有 labels.json 就用它，否则用内置标注
python eval_threshold.py --labels builtin # 强制用内置的人工标注集
```

用人工标注集评估不同阈值下的 precision / recall / F1，并对比稳健模板与简单平均的效果。修改算法或换角色后，先跑这个确认指标没有回退。

标注来源有两种：界面上点「保存人工样本」写的 `labels.json`，或脚本内置的 32 句（人工逐条核对过）。**注意**：界面保存的标注本身就是阈值筛出来的，如果没逐条核对，在对应阈值上的指标会偏乐观（示例里会显示 F1 1.000 @ 0.66）。看独立评估用 `--labels builtin`。

有负样本时会额外做 margin 扫描（0.05–0.5），打印各档最佳 F1 与 0.66 处的 F1。当前数据集上负样本抑制没有带来提升，所以生产逻辑默认不启用。

### import_legacy.py

```bash
python import_legacy.py           # 先看时长对比，不会写入
python import_legacy.py --yes     # 确认归属后导入
```

旧版把产物直接放在 `work/` 下，没有来源记录。这类文件无法自动判断属于哪个视频，所以只提供手动导入。脚本会先打印源视频与旧转写的时长，不匹配直接拒绝；加 `--yes` 才会建立运行并校验。

### migrate_jobs.py

```bash
python migrate_jobs.py --dry-run    # 只打印计划
python migrate_jobs.py              # 实际改名并升版
python migrate_jobs.py --rehash     # 忽略指纹缓存重新计算
```

两件事一起做：

1. **指纹升级**：v3 的任务 ID 来自头尾采样哈希，v4 换成完整文件指纹。脚本按清单记录的源路径重算，校验文件大小与时长都没变之后才改名，并把 runs 内转写和 `selected.json` 的 `source_id` 一并改写。任何一项对不上就跳过，不做猜测。
2. **音频归位**：把任务根目录的 `audio16k.wav` / `audio.json` 移进活动 run 目录，之后清理旧 run 时音频会跟着走。

`--rehash` 用于怀疑指纹缓存命中旧摘要（同尺寸同 mtime 原地改写）时强制重算。

## 任务队列

界面的「任务队列」页签把「分析 → 筛选 → 导出 → 清单」串成一条批处理流水线，适合一次处理多集或多角色。

```text
左栏设好参数 → 「加入当前视频」→ 换视频/角色再加 → 设输出目录 → 「开始队列」
```

- 每条记住加入时的全部参数（角色、特征词、阈值、留白、音轨、分辨率、CRF、帧率模式），之后改界面不影响已排队的条目
- 执行时自动判断：已有匹配的分析结果就跳过分析，只跑 `select → cut → gen_report`；没有或音轨变了就跑完整流水线
- 状态：等待 / 进行中 / 完成 / 失败 / 已取消，说明列显示复用了哪个运行或失败原因
- 队列保存在 `work/queue.json`，关掉程序再打开还在；上次被强杀时停在「进行中」的条目会回到「等待」
- 串行执行，不并发：显存和 CPU 只有一份

命令行等价操作就是依次跑 `select.py → cut.py → gen_report.py`，队列只是把参数固化下来并加了状态管理。

## 常见改动

**只重切某几段**（不重新转写，最省时间）
改 `select.py` 的 `--ids`，或直接在 GUI 里勾选 → 跑 `cut.py` → 跑 `gen_report.py`，约 1 分钟。

**调整片段疏密**
- 更连贯：调大 `--merge-gap`（如 3.5）
- 更紧凑：调小 `--merge-gap`（如 1.0）、减小 `--pad-*`
- 避免带入别人尾音：减小 `--pad-tail`

**换一集处理**
1. 视频放进 `input/`
2. 跑 1→2→3，任务目录会自动建立
3. 跑 `eval_threshold.py` 或看 GUI 的分数分布，确定特征词和阈值
4. 跑 `select.py` → `cut.py` → `gen_report.py`

## 注意事项

- **装包用** `.venv/Scripts/python.exe -m pip install xxx`。直接调 `Scripts/pip.exe` 会失败——venv 移动过，pip.exe 里内嵌的旧路径已失效。
- **不要升级 `av`**。faster-whisper 1.2.1 与 `av>=15` 不兼容；本项目用 scipy 读 WAV 后直接传 numpy 数组，绕开了 av 解码。
- **不要覆盖** `models/spkrec-ecapa-voxceleb/hyperparams.yaml`。该文件已删掉 `label_encoder` 加载项，旧格式与新 speechbrain 不兼容。
- **GPU 需要 cuDNN 9**。当前机器可用；换机器若无 CUDA，转写自动降级 CPU，25 分钟音频约需 10–15 分钟。
