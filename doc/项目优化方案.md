# 项目优化方案

## 1. 项目概况

本项目是一个 Windows 本地离线运行的动画角色台词剪辑工具，主要流程为：

```text
视频抽取音频
  -> Whisper 日语转写
  -> ECAPA-TDNN 声纹提取
  -> 使用已确认台词建立角色声纹模板
  -> 相似度筛选与人工核对
  -> FFmpeg 切割、转码和拼接
  -> 生成成片与核对清单
```

当前项目已经具备可用的 GUI、命令行流水线、本地模型和 FFmpeg 工具。`scoring.py` 与 `segmenter.py` 已被 GUI 复用，整体结构简单，现有样本也能够完整生成结果。

本次审阅覆盖：

- `gui/` 下全部界面与任务调度源码
- `work/` 下全部流水线与算法源码
- 根目录说明、启动脚本和忽略规则
- 模型、虚拟环境、输入、缓存及输出目录的结构与元数据
- 现有转写、声纹、切点和成片的一致性

第三方虚拟环境源码、模型权重和 FFmpeg 二进制仅检查了目录结构、版本及体积，没有逐文件审阅其内部实现。

## 2. 当前验证结果

- 全部一方 Python 文件通过 `compileall` 语法检查。
- 当前样本包含 403 个转写语段和 399 个声纹向量。
- 当前方案包含 14 个有效切片，总时长 120.43 秒。
- 所有切片均位于原视频时间范围内，没有负时长或越界数据。
- 输入样本为 3840 x 2160、约 23.976 fps，现有固定导出参数恰好适配该样本。
- 项目目前没有测试目录、依赖清单或依赖锁文件。
- `work/verify.py` 所需的 `work/probe.wav` 不存在，因此自检脚本无法按文档正常执行。
- 当前环境没有可用的 `git` 命令，无法确认工作区提交及未提交改动状态。

## 3. 问题与风险

### P0：缓存没有绑定源视频

相关位置：

- `gui/main.py:289`：选择视频时只更新视频路径和时长
- `gui/main.py:323`：启动时直接加载固定的 `work/transcript.json` 和 `work/embeddings.npz`
- `gui/main.py:483`：只要内存中存在语段和勾选项就允许导出
- `work/transcribe.py:77`：转写产物没有记录源视频身份

切换视频后，界面仍可能保留上一部视频的转写、声纹、得分和勾选结果。此时用户可以直接生成成片，程序会用旧时间码切割新视频。这是当前最严重的结果正确性问题。

建议：

1. 为每次分析建立独立任务目录，例如 `work/jobs/<source-id>/`。
2. 在 `manifest.json` 中保存源文件路径、文件大小、修改时间、时长、模型、语言和产物格式版本。
3. 加载缓存前校验 manifest 与当前视频是否一致。
4. 切换视频时立即清空旧语段、声纹、得分和勾选状态，并禁用导出。
5. 所有产物先写临时文件，全部成功后再原子替换正式文件，避免失败任务留下半套新旧混合数据。

### P0：报告仍然绑定特定作品和角色

相关位置：

- `work/gen_report.py:18`：报告文件名固定为“碧翠丝片段清单”
- `work/gen_report.py:62`：报告标题固定为碧翠丝
- `work/gen_report.py:63`：作品与集数固定为第 8 话
- `work/gen_report.py:67`：原片时长固定为 25 分 19 秒
- `work/gen_report.py:68`：保留比例使用固定时长 1519.53 秒

处理其他视频或角色时，成片可能正确，但报告内容会错误，且不同任务会互相覆盖报告文件。

建议将以下信息写入 `selected.json` 或任务 manifest：

- 源视频名称与时长
- 目标角色名称
- 生成时间
- 模型和阈值
- 每条台词的实际相似度
- 输出文件路径

报告应完全根据这些字段生成，并使用视频名和角色名生成唯一文件名。

### P0：导出参数会改变部分素材

相关位置：

- `work/cut.py:23`：帧率固定为 `24000/1001`
- `work/cut.py:24`：直接缩放到固定宽高
- `work/cut.py:42`：所有视频强制使用固定帧率

当前样本恰好为 16:9 和约 23.976 fps，因此没有暴露问题。对于其他帧率、竖屏或非 16:9 视频，可能发生补帧、丢帧或画面拉伸。

建议：

1. 默认提供“保持源规格”模式，使用 ffprobe 获取宽高、帧率、像素比例和旋转信息。
2. 未明确要求时不传固定 `-r`。
3. 缩放时保持宽高比，并让用户选择限制最长边、补边或裁剪。
4. 明确映射首个视频流和选定音轨，避免附件或多音轨素材产生歧义。
5. 输出先写入临时文件，成功后再替换最终文件。

### P0：环境自检脚本不可用

相关位置：

- `work/verify.py:47`：直接读取不存在的 `work/probe.wav`
- `work/verify.py:49`：强制使用 CUDA，没有 CPU 回退

这与 README 中“GPU 可选、无 CUDA 自动降级 CPU”的说明不一致。

建议：

- 从现有音频截取几秒作为临时探针，或随项目提供一个很小的无版权测试音频。
- 使用与正式转写相同的 CUDA 到 CPU 回退逻辑。
- 每项检查独立捕获异常，最终输出完整的通过/失败清单并返回正确退出码。
- GUI 启动时执行轻量检查，开始分析前再检查模型和设备。

### P1：人工核对缺少试听能力

当前 GUI 只能显示时间码、转写文本和相似度。短句、BGM 覆盖、重叠说话和相似声线恰好是项目文档中列出的主要误判来源，仅看识别文本无法可靠确认说话人。

建议在表格中加入：

- 双击台词播放对应原片片段
- 播放、暂停、前后跳转和循环当前句
- 自动加入少量试听留白
- “仅显示阈值附近”过滤器
- 按相似度、时间和勾选状态排序
- 上一条/下一条及勾选快捷键
- 可选的波形或播放进度显示

这项改进会直接提高人工复核效率和最终准确率，应排在算法升级之前。

### P1：无用聚类仍在主流水线中执行

相关位置：

- `work/voiceprint.py:53`：逐条执行声纹编码
- `work/voiceprint.py:75`：对同一批向量执行六次层次聚类
- `work/voiceprint.py:81`：样本数过少或每个样本独立成簇时，轮廓系数可能报错

README 已说明聚类结果不适合当前动画素材，GUI 的角色判断也只使用种子模板分数。因此聚类会增加耗时和失败面，却不影响最终结果。

建议：

1. 声纹提取完成后立即保存 embeddings。
2. 将聚类移动到单独的可选诊断命令。
3. 补齐空转写、单语段、全短句和无有效聚类等边界处理。
4. 在确认结果一致后，尝试批量填充音频并批量计算 embeddings，减少逐句模型调用。

### P1：停止操作可能留下 FFmpeg 进程

相关位置：

- `gui/runner.py:47`：取消时只终止当前 Python `QProcess`
- `work/cut.py:45`：Python 进程内部又启动 FFmpeg

终止 Python 后，其 FFmpeg 子进程可能继续编码并覆盖输出文件。

建议：

- 让调度层直接管理 FFmpeg 进程，或在 Windows 上为任务建立可统一终止的进程组/Job Object。
- 取消后等待进程退出，清理本次任务的临时文件。
- 保留原有正式输出，只有新文件完整生成后才替换。
- 补充应用关闭窗口时的任务终止处理。

### P1：模型选项与离线能力不一致

相关位置：

- `gui/main.py:120`：GUI 提供 `large-v3`、`medium` 和 `small`
- `work/transcribe.py:24`：直接按模型名称加载，缺失时可能访问网络

项目中只发现 `large-v3` 模型。选择其他模型可能触发下载或直接失败，与“全程本地离线”承诺不一致。

建议只显示本地已安装模型，另设明确的模型管理入口。离线运行时设置 `local_files_only` 或等价机制，并给出可理解的缺失提示。

### P2：工程可维护性不足

目前脚本普遍在模块顶层直接执行，并通过 `sys.argv` 读取位置参数。`select.py` 和 `seed_match.py` 仍保留单集专用的角色编号与时长。项目没有 `requirements.txt`、`pyproject.toml` 或版本锁文件。

建议：

- 将各脚本拆成可导入函数，并使用 `argparse` 定义 CLI。
- 新建统一的路径、任务配置和产物模型。
- GUI 和命令行调用同一服务层，避免两套逻辑分叉。
- 记录 Python 和直接依赖的精确版本。
- 提供环境创建脚本；便携发行版可继续携带虚拟环境，但开发环境不应依赖复制现成 `.venv`。
- 删除或合并重复模型缓存，提供“轻量源码包”和“完整离线包”两种分发方式。

## 4. 算法优化方向

### 4.1 稳健的声纹模板

当前实现将所有种子向量直接平均。当种子中混入误识别、强音效或情绪极端的台词时，模板会被明显拉偏。

可按以下顺序改进：

1. 计算种子之间的两两相似度，自动标出离群种子。
2. 使用中位中心、截尾平均或先剔除离群点再求均值。
3. 为平静、喊叫、耳语等声线建立多个原型，使用最高相似度作为结果。
4. 支持少量明确的反例，为易混淆角色增加负向约束。
5. 保存人工勾选和取消记录，用作下一轮重新评分的正负样本。

### 4.2 用标注集选择阈值

固定阈值 `0.62` 来自单集经验，不一定适用于其他角色、作品或音轨质量。

建议建立一个小型人工标注集，至少记录：

- 目标角色与非目标角色标签
- 声纹得分
- 台词时长
- 是否含 BGM、重叠说话或明显音效

基于该数据输出 precision、recall、F1 和不同阈值下的候选数量。GUI 可以给出建议阈值，同时保留人工调整能力。

### 4.3 提升短句处理质量

短句可尝试与相邻同说话人候选共同编码，或在不跨越其他角色语段的前提下扩大音频窗口。所有改动都应先在标注集上验证，防止增加上下文后混入其他角色声音。

## 5. 测试方案

### 单元测试

- 相邻台词的合并与不合并
- 其他角色插话时的边界避让
- 视频起点、终点和极短语段
- 缺失 ID、重复 ID、空选择和越界时间
- 空种子、无效种子和零向量模板
- manifest 匹配与缓存失效
- 报告中的动态标题、时长、得分和文件名

### 集成测试

准备一个数秒钟的无版权测试视频，覆盖：

- 16:9、竖屏和非标准宽高比
- 23.976、25 和 30 fps
- 单音轨和多音轨
- CPU 模式及 CUDA 不可用时的回退
- 分析失败、导出失败和用户取消
- 成片时长、音画同步、分辨率和帧率检查

### 回归测试

保留一组小型人工标注数据，对声纹算法变更比较 precision、recall 和 F1。算法优化只有在指标明确改善时才进入默认流程。

## 6. 分阶段实施计划

### 第一阶段：保证结果正确

目标：任何视频都不会误用其他任务的数据，输出和报告与当前任务一致。

- 引入任务 manifest 和按视频隔离的缓存目录
- 切换视频时清空旧状态并禁用导出
- 报告去除作品、角色和时长硬编码
- 导出保持源帧率和画面比例
- 修复环境自检
- 临时文件与正式输出分离

验收标准：连续处理两个不同视频时，第二个任务无法读取或导出第一个任务的数据；报告与媒体探测信息完全一致。

### 第二阶段：提高人工复核效率

目标：用户能在 GUI 内完成完整核对，不需要另开播放器查时间码。

- 增加内嵌试听或视频预览
- 增加不确定项过滤和排序
- 增加键盘快捷操作
- 保存人工修正状态
- 改善真实进度反馈和取消行为

验收标准：用户可以只通过 GUI 听完全部不确定项、调整勾选并生成成片。

### 第三阶段：整理工程结构

目标：GUI、CLI 和测试共用同一套实现，环境可以稳定重建。

- 抽取服务层和统一配置
- 使用 `argparse` 规范命令行参数
- 增加依赖清单与版本锁
- 增加单元测试和小型端到端测试
- 将聚类移出主流水线
- 完善错误分类和日志

验收标准：新环境可按文档重建；核心测试自动通过；GUI 与 CLI 对同一参数生成一致切点。

### 第四阶段：算法与性能优化

目标：在有客观评估数据的基础上减少误判和处理时间。

- 稳健模板与多原型评分
- 正负样本联合校准
- 短句上下文策略
- 批量声纹编码
- 基于标注集自动建议阈值

验收标准：在固定标注集上准确率指标改善，且处理时间没有不可接受的回退。

## 7. 推荐优先顺序

建议按以下顺序执行：

1. 修复缓存与源视频错配。
2. 通用化报告和输出命名。
3. 保持源视频帧率及宽高比。
4. 修复自检和取消行为。
5. 增加试听与不确定项复核功能。
6. 建立测试与依赖锁定。
7. 重构脚本边界。
8. 使用标注集推进算法优化。

前四项直接影响结果正确性，应优先于界面美化和模型调参。
