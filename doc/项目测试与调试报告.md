## 3. Bug 与 Debug 方案

### P0-1：旧缓存可能迁移给无关视频

相关代码：

- `gui/main.py:351`
- `work/core/manifest.py:110`

#### 现象

GUI 在发现当前视频没有任务缓存时，会尝试迁移根目录中的旧版扁平缓存。迁移逻辑只比较转写时长与当前视频时长，没有验证视频内容，`source_path` 参数也没有实际参与校验。

已通过最小复现确认：构造一个无关视频身份，只要时长与旧转写接近，程序就会把旧 `transcript.json` 和 `embeddings.npz` 复制到新任务目录，并生成看似有效的 manifest。

#### 风险

旧视频的时间码和声纹可能被用于剪辑新视频，直接产生错误成片。

#### Debug 方案

1. 暂停 GUI 中的自动旧缓存迁移。
2. 将旧缓存迁移改成用户明确触发的一次性导入。
3. 为源视频计算内容指纹，例如：文件大小加首尾各 1 MiB 的 SHA-256。
4. 旧缓存没有来源指纹时，不得自动绑定到任何新任务。
5. 增加“相同时长但不同内容不得迁移”的回归测试。

### P0-2：分析产物不是任务级原子更新

相关代码：

- `work/transcribe.py:106`
- `work/voiceprint.py:121`
- `work/core/manifest.py:89`

#### 现象

转写阶段先覆盖任务目录中的 `transcript.json` 并更新 manifest，声纹阶段随后才覆盖 `embeddings.npz`。`has_analysis()` 只检查两个文件是否存在，没有判断它们是否属于同一次分析。

如果重新分析时声纹阶段失败或被取消，目录中可能留下：

- 新转写
- 旧声纹
- 已更新的 manifest

下次启动时，这套混合数据仍可能被当作完整分析结果加载。

#### Debug 方案

1. 每次分析写入 `work/jobs/<source-id>/runs/<run-id>/` 临时目录。
2. manifest 增加 `run_id` 和 `status` 字段。
3. 流程开始时写入 `status: running`。
4. 完成后验证 transcript source ID、embedding ID、数量和维度。
5. 校验通过后将状态改为 `complete`，再原子更新 `active_run`。
6. GUI 只加载状态为 `complete` 的活动运行。
7. 增加“转写成功但声纹失败”的故障注入测试。

### P0-3：多段成片存在时长漂移

相关代码：

- `work/cut.py:31`
- `work/cut.py:84`
- `work/cut.py:101`

#### 现象

当前切点计划总长为 101.99 秒，实际成片时长为 103.452 秒，多出 1.462 秒。14 个片段平均每段累计约 0.104 秒误差。

输出媒体还出现以下差异：

- 源视频名义帧率：约 23.976 fps
- 成片平均帧率：约 23.726 fps
- 视频起始时间：0.021 秒

#### 原因判断

当前方案将每个片段分别编码为带 AAC 音频的 MP4，然后使用 concat demuxer 流复制拼接。AAC 编码器延迟、MP4 时间基和每段时间戳舍入误差会在多段拼接时重复累计。

#### Debug 方案

建议改为单次 FFmpeg 处理：

1. 使用一个输入文件。
2. 每个视频段使用 `trim` 和 `setpts`。
3. 每个音频段使用 `atrim` 和 `asetpts`。
4. 使用 concat filter 拼接处理后的音视频流。
5. 最终只进行一次 H.264 和 AAC 编码。

修复后的验收标准：

- 成片总长与计划总长误差小于 50 ms 或一帧
- 音频与视频结束时间误差小于一帧
- 时间戳单调递增
- CFR 源素材的输出平均帧率与源一致
- 1、2、14 和大量片段场景均有自动测试

### P1-2：任务 ID 仍可能碰撞

相关代码：

- `work/core/manifest.py:21`

#### 现象

当前任务 ID 由文件名、文件大小和整数秒级修改时间生成。测试中，两个不同目录下同名、同大小、同修改时间但内容不同的文件生成了完全相同的任务 ID。

#### Debug 方案

- 使用内容指纹作为主身份。
- 路径、文件大小和修改时间作为缓存快速失效信息。
- `matches()` 必须比较内容指纹。
- 增加任务 ID 碰撞测试和文件内容变化测试。

### P1-3：CLI 参数边界存在问题

#### 裸输出文件名导致异常

执行：

```powershell
.venv\Scripts\python.exe work\cut.py --video input\re0_1_08.mp4 --output bare-name.mp4
```

结果：`os.path.dirname()` 返回空字符串，随后 `os.makedirs("")` 抛出 `FileNotFoundError`。

相关代码：`work/cut.py:72`。

修复方式：将输出转换为绝对路径，或只在目录名非空时创建目录。

#### 角色名没有文件名净化

角色名会直接进入成片和报告文件名。Windows 中的 `/`、`:`、`*`、`?` 等字符会导致失败或产生意外目录。

相关代码：

- `gui/main.py:578`
- `work/cut.py:71`
- `work/gen_report.py:44`

修复方式：在核心模块增加统一的 `safe_filename()`，所有输出入口共用。

#### 显式 ID 的评分种子语义不清

使用 `select.py --ids` 选择其他角色时，报告中的分数仍可能使用默认关键词 `かしら,ベティ` 建立模板。

相关代码：`work/select.py:81`。

修复方式：拆分 `--selected-ids` 和 `--seed-ids`；显式 ID 模式下，没有种子就不生成声纹分数，或者明确要求提供种子。

## 5. 下一步建议

### 第一阶段：修复数据正确性

优先完成：

1. 禁止不可靠的旧缓存自动迁移。
2. 引入分析 run ID 和完整状态提交机制。
3. 将剪辑改为单次 filter graph 编码。

这四项完成前，不建议继续扩展批量处理或自动化导出。

### 第二阶段：完善交互和 CLI

随后处理：

1. 关键词零命中时仍显示全部语段。
2. 统一输出文件名净化。
3. 明确 CLI 的选择 ID 与模板种子 ID。
4. 重写或移除旧版 `seed_match.py`。
5. 在 GUI 中显示缓存状态、分析 run ID 和失败原因。

### 第三阶段：提高人工复核效率

在数据链路稳定后增加：

- 内嵌试听或视频预览
- 循环当前台词
- 仅显示阈值附近候选
- 按分数、时间和勾选状态排序
- 键盘快速勾选与跳转
- 保存人工正负样本

### 第四阶段：继续优化算法

当前稳健模板的 F1 已优于简单平均模板，默认阈值也有标注数据支持。下一步算法工作应基于更多作品和角色的标注集，重点评估：

- 多声线原型
- 明确负样本
- 短句上下文扩展
- BGM 与重叠说话分组评估
- 跨集阈值稳定性

## 6. 综合评价

本轮优化显著改善了项目结构和可维护性，主要纯函数和模型链路工作正常。当前风险已经从“普遍硬编码”收敛为几个具体的数据生命周期和媒体时间轴问题。

下一轮应把可靠性作为主线：保证缓存不会串任务、分析不会混合产物、成片时间轴不会随片段数量漂移。完成后，项目才适合继续增加试听、批量处理和更复杂的角色识别能力。
